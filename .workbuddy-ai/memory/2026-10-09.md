## 新建 skill: yq-pay（业桥支付中心 · 模拟支付成功）

位置：`/Users/qckj/skills/skills/yq-pay/`（同时软链到 `~/.workbuddy-ai/skills/yq-pay`）。

技术栈：TypeScript + tsx（对齐 gitlab-skill 风格），stdout 输出 JSON、stderr 输出过程日志。零配置，开箱即用。

命令：
- `query <订单号> [--date YYYY-MM-DD]`
- `mock <订单号> [--dry-run] [--force] [--no-verify]`（查询 → 选通知接口 → 模拟支付成功 → 复核状态）
- `notify <payOrderId> --vendor ICBC|SHENGJING|WX`

接口要点（已实测确认）：
- 查询：`POST https://apideve.yeqiao.cn/dev-api/admin/payOrderSub/getPaymentOrderList`，multipart，`select_payOrderNum` 同时匹配 `mchOrderId`(SC…)/`payOrderId`(P…)/`tradeNo`(T…)，**`select_date` 留空即全量跨日期检索**；响应 `{total, mes, resultList, status}`。
- 通知：`POST http://10.10.100.44:3030/payCenter/notify/simulate/payNotifyRes/{厂商}`，body `{"payOrderId":"P..."}`；响应 `{code:200,msg:"操作成功",data:null}`，`code===200` 为成功（失败为 code 500）。
- 厂商映射：中国工商银行/ICBC → ICBC；盛京银行/SHENGJING → SHENGJING；业乔科技/YQ → WX。
- 同一订单号可能存在多条支付记录（多次支付尝试），已实现优先取「未支付且最新」的一条。

验证：tsc --noEmit 通过；query / mock --dry-run / 已支付跳过 / 多候选择优 / 非 SC 前缀订单 / 错误分支均实测通过。未执行真实 mock 通知（需用户确认订单号）。

## 追加：通知失败（code != 200）的提示处理

通知接口 HTTP 恒为 200，业务结果看响应体 `code`。已实现：
- `src/client.ts` 新增 `describeFailure()` 与 `formatNotifyFailure()`，从 `data.stackTrace[0]` 提取异常位置（`类名.方法:行号`）。
- `NotifyResult` 增加 `failure?: { code, msg, location }`；失败时 stdout JSON 带 `notify.error`，stderr 打印「接口已正确调用但支付中心返回失败」的提示语，退出码 1。
- `SKILL.md` 新增强制规则：`code !== 200` 时必须如实告知用户 mock 失败，不得含糊报成功，且不要反复重试。
