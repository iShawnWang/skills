# 发版 Memory

这里保存 `release-skill` 的持久化发版历史。

## releases.jsonl

`releases.jsonl` 是一个追加式历史记录文件。

每一行代表一次发版操作。

它不是静态的发版规则配置。

例如同一个分支可能出现：

```text
feat/foo → test
feat/foo → pre
feat/foo → test
```

这些都是历史事实，应该全部保留。

AI 应该根据历史记录帮助推断当前用户的发版意图，但当前用户的明确要求始终拥有最高优先级。

## 记录原则

- 新操作追加记录。
- 不修改历史记录。
- 不删除历史记录。
- 不把历史记录当成永久规则。
- 成功和失败的操作都可以记录。
- 成功操作作为主要的推断依据。
- 用户明确改变发布方式时，新增一条记录。
- Git 仓库本身同时提供 Memory 的版本历史和审计能力。
